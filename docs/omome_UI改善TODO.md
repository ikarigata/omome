# omome UI 改善 TODO

現状のフロントエンド実装（`frontend/src`）を一通りレビューして洗い出した、UI/UX・見た目の改善候補。
機能としては動くが、フィードバック・空状態・アクセシビリティ・モバイル最適化に伸びしろがある。

優先度の目安: **P1** = 体験を明確に損ねている / 早めに直したい、**P2** = あると良い、**P3** = 余裕があれば。
チェックは未着手。実装したら設計書（`omome_フロントエンド設計書.md`）側にも反映して同期を保つこと。

## 1. 全体・共通基盤

- [ ] **ログアウト導線が UI に存在しない**（P1）。`useAuth` に `logout` はあるが、どの画面からも呼べない。ヘッダー右かホームにプロフィール/メニュー（… or アバター）を置き、ログアウトを露出する。
- [ ] **エラーフィードバックの仕組みがない**（P1）。ミューテーション失敗時、`ExercisesPage` と Login/Signup 以外（ホーム、カレンダー、WorkoutDay の削除/更新、SetInput、ExerciseSelect）はエラーがユーザーに一切見えない。トースト（sonner 等）を導入し、`onError` で共通表示する。設計書 §エラー正規化（401/403/404/400/409/500）の方針と接続する。
- [ ] **成功フィードバックがない**（P2）。保存・追加・削除の成功時に軽いトースト or マイクロアニメーションを出す。
- [ ] **ローディングが「読み込み中…」テキストのみ**（P2）。一覧系（ホーム/種目/カレンダー）にスケルトンUIを入れて体感速度を上げる。
- [ ] **ネイティブ `confirm()` / `alert()` を使用**（P2）。WorkoutDay 削除・記録削除・種目削除が `confirm()`。アプリのトーン（DotGothic16 のレトロ調）に合う確認モーダルコンポーネントに置き換える。
- [x] **PC幅で全幅に広がる**（P2）。モバイル前提のレイアウトだが max-width 制約がない。ルートを `max-w-md mx-auto` 等で中央寄せし、広い画面でも破綻しないようにする。→ `PageLayout` ルートと `BottomNav` 内側を `max-w-md mx-auto` で中央寄せ。
- [ ] **アクセシビリティ全般**（P2）。アイコンのみのボタン（ドラッグハンドル `⠿`、削除 `✕`、メイン指定 `★`、BottomNav の各アイコン）に `aria-label` がない。NavLink に `aria-current` を付与。フォーカス可視化を全インタラクティブ要素で担保する。
- [ ] **本文タイポグラフィの可読性**（P3）。DotGothic16 をピクセルフォントとして全面採用しており、小さい文字（カレンダー 9px 等）が読みにくい。見出しはドット、本文/数値は可読フォントに分ける運用を検討。
